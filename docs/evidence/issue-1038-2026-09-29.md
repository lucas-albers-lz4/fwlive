## Installed LuCI disclosure check

Used an isolated copy of the existing OpenWrt 24.10.8 x86_64 lab disk,
revision `r29233-443ec4032a`, with source-synced candidate view/modules and
rpcd plugin. Ports: HTTP 8088, SSH 2228. This is source-sync evidence;
package installation, upgrades, and translation-package loading were not
retested. The shipped ACL was unchanged.

The real `ubus call fwlive rules` returned a usable nft map with
`truncated: false`. The required QEMU log-pipeline smoke passed with three
parsed firewall events.

```sh
OPENWRT_SSH_PORT=2228 OWRT_HOSTFWD_HTTP=8088 \
  ./scripts/qemu-smoke-fwlive.sh --require-log-pipeline
FWLIVE_URL=http://127.0.0.1:8088 \
  FWLIVE_RULES_DETAILS_OUT=/tmp/fwlive-1038-evidence \
  node tests/fwlive-rules-diagnostics-lab.mjs
```

The browser check uses the installed LuCI module and its real DOM. It injects
combined/unknown-code states into that module; these cases are UI evidence,
not installed backend fault injection. The backend combinations have host
fixture evidence instead.

At 1280×900 with keyboard and 390×844 with touch:

- Healthy lookup hid Details; the combined state exposed one warning and an

- Enter/tap expanded both causes, quotable diagnostic codes, the firewall
  explanation, and the friendly-name search caveat.
- Unknown HTML-like codes remained literal text nodes.
- Recovery hid and closed the disclosure. The diagnostic interactions
  produced no page errors.
