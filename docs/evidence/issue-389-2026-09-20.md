## Installed lifecycle checks

The strict checks start with no WAN `log` option and no baseline file, enable
logging through ubus, then remove the package and assert that the original
state is restored and `/etc/fwlive/wan-log-baseline` is removed.

| OpenWrt 24.10.8 armsr/armv8 (QEMU, port 2222) | `opkg remove luci-app-fwlive` | **PASS** — `ipk_lifecycle_passed` |

The 24.10 IPK is `_all` and therefore architecture-independent. This is the
representative IPK format used for the supported 23.05/24.10 package surface;
the existing 23.05 x86 QEMU smoke coverage remains the runtime check for that
release. No separate 23.05 build was needed for this package-format check.

## Runtime prerequisite and bounded backend distinction

The stock 24.10.8 and 25.12.0 lab images contain `nft`/fw4 but do not contain
the `timeout` utility. Before installing the official `coreutils-timeout` lab
package, fwlive correctly reports `timeout_missing` and `rules` returns
`backend: unknown`, `error: no_backend`. With that prerequisite installed,
the same guests report `backend: nft` and have no timeout warning. This is an
image prerequisite distinction, not a package failure.

The installed guests also exercised `logging_status`, `rules`, `poll`, and
`resolve`, plus the enable/disable WAN logging paths. Read methods remained
separate from the write methods and no `ubus log.read` permission was added.
