`luci-app-fwlive` 0.1.44-r1. The package hook is defined before LuCI's
`BuildPackage` invocation so both package formats carry the WAN-log baseline

## Released v0.1.44 hook mismatch

Tag `v0.1.44` shipped `[ "$1" = "remove" ] || exit 0` in `prerm-pkg`. Through
the installed opkg wrapper, `$1` is the wrapper **path**, so that guard never
fired. Pre-#405 "#389 live opkg remove verified to restore" was taken against
a lab-planted `prerm` in `scripts/qemu-install-fwlive.sh` that #405 deleted.
Master-era lab installs with the planted always-restore script restore once on
the next version bump; tagged field users had the v0.1.44 non-matching body.
`docs/release.md` keeps `PKG_RELEASE:=1` and bumps the third octet at release,
so the fix ships at the next `v*` tag.

### Same-version preservation checks (not hook proof)

These cells confirm that a no-op reinstall does not disturb an enabled WAN log
bit and baseline file. They do **not** exercise the skip-upgrade `prerm` body.
The discriminating inputs are `upgrade` and `PKG_UPGRADE=1`, which host tests on
#405 model against extracted `prerm-pkg`.

| Guest | Package manager | Result |
| --- | --- | --- |
| OpenWrt 24.10.8 x86_64 (QEMU, port 2222) | same-version `opkg install` (up-to-date) | **PASS** (no-op preservation) — opkg runs **no maintainer script** when already installed; preserved `log=1` and baseline are unchanged |
| OpenWrt 25.12.5 x86_64 (QEMU, port 2223) | `apk add --force-reinstall` | **PASS** (no-op preservation) — ran `post-upgrade` only (no `pre-deinstall`); preserved `log=1` and baseline |

On 25.12, `apk add --force-reinstall` emits
`Replacing ... (0.1.44-r1 -> 0.1.44-r1)` and runs `post-upgrade` without
running `pre-deinstall`; a real `apk del` runs `pre-deinstall` with the old
version. The hook therefore treats the version-shaped argument as the APK
uninstall signal and treats empty, unknown, and explicit upgrade actions as
fail-closed. This is not a claim about a cross-release 24.10-to-25.12
sysupgrade, which is not a supported package-manager operation.

The 24.10 IPK is `_all` and therefore architecture-independent. This is the
representative IPK format used for the supported 23.05/24.10 package surface;
the existing 23.05 x86 QEMU smoke coverage remains the runtime check for that
release. No separate 23.05 build was needed for this package-format check.
The QEMU installer does not overwrite package maintainer scripts, so these
checks exercise the scripts shipped by the IPK/APK artifacts.

## Runtime prerequisite and bounded backend distinction

The stock 24.10.8 and 25.12.5 lab images contain `nft`/fw4 but do not contain
the `timeout` utility. Before installing the official `coreutils-timeout` lab
package, fwlive correctly reports `timeout_missing` and `rules` returns
`backend: unknown`, `error: no_backend`. With that prerequisite installed,
the same guests report `backend: nft` and have no timeout warning. This is an
image prerequisite distinction, not a package failure.
