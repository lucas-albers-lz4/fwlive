# Issue #392 installed authenticated-session evidence — 2026-09-20

This record covers the R4b boundary that host tests cannot establish: rpcd
assigning the shipped ACL to an authenticated LuCI/uhttpd session, denying
`log.read` to that granted session, and denying sampled fwlive read/write
methods to an authenticated session without that ACL. The deny session is not
an exhaustive method sweep.

## Artifact

- Guest: OpenWrt 24.10.8, `x86_64`, QEMU/KVM, host SSH port 2222, LuCI HTTP port 8080
- Package: `luci-app-fwlive` `0.1.44-r1` IPK
- Tested source: `7702ff3ca0699187cb9e1fd0c0a9f179af1dfbf4` (`source_state=clean`)
- Installed rpcd SHA-256: `96babf2ee4346af697edd2f780befc0abbe32d7c747212fe294fa90c0398aa3c` (matches in-tree `openwrt-feed/luci-app-fwlive/root/usr/libexec/rpcd/fwlive`)
- Installed ACL SHA-256: `6bfcb9ae2a9927969a11cd7fcf59e24ed92c44615d043cc61843402a7fd23d49` (matches in-tree `openwrt-feed/luci-app-fwlive/root/usr/share/rpcd/acl.d/luci-app-fwlive.json`)
- Command: `OPENWRT_SSH_PORT=2222 OWRT_HOSTFWD_HTTP=8080 ./scripts/qemu-acl-session-smoke.sh`

The guest reported `backend: "unknown"` because the image does not include
the optional `timeout` utility. That image prerequisite does not affect the
HTTP session ACL boundary; the fwlive rpcd object and ACL were installed and
the session calls below reached the dispatcher.

## Temporary session identities

The smoke created two temporary rpcd logins, authenticated them over
`POST /ubus`, and restored `/etc/config/rpcd` in its exit trap:

- `fwlive-acl-grant`: read/write `luci-app-fwlive` ACL group
- `fwlive-acl-deny`: read `luci-base`, with no fwlive ACL group

The test password is deliberately omitted. Unless
`FWLIVE_ACL_TEST_PASSWORD` is supplied, the helper creates a per-run
lab-only password and never writes or prints it.

## Results

The granted authenticated session returned JSON-RPC result `0` for all six
declared fwlive methods. The same session was denied `log.read` with the
JSON-RPC Access denied code `-32002`. The deny session was checked on one
read method and one write method only.

| Session | Method | Result |
| --- | --- | --- |
| `fwlive-acl-grant` | `fwlive.logging_status` | allowed (`0`) |
| `fwlive-acl-grant` | `fwlive.rules` | allowed (`0`) |
| `fwlive-acl-grant` | `fwlive.poll` | allowed (`0`) |
| `fwlive-acl-grant` | `fwlive.resolve` | allowed (`0`) |
| `fwlive-acl-grant` | `fwlive.enable_wan_logging` | allowed (`0`) |
| `fwlive-acl-grant` | `fwlive.disable_wan_logging` | allowed (`0`) |
| `fwlive-acl-grant` | `log.read` | denied (`-32002`) |
| `fwlive-acl-deny` | `fwlive.logging_status` | denied (`-32002`) |
| `fwlive-acl-deny` | `fwlive.enable_wan_logging` | denied (`-32002`) |

The helper snapshots and restores the original WAN logging state. Cleanup
reverts any staged UCI overlay, restarts rpcd from the restored configuration,
verifies the restored `/etc/config/rpcd` SHA-256 against the backup, prints
`guest rpcd backup restored and hash verified`, and only then removes the
backup. The helper does not emit `RPCD_RESTORED=yes` and does not grep
`/etc/config/rpcd` for leftover users; the hash match is the cleanup oracle.
A manual post-run check saw `wan_log` false and no temporary login remaining
in `/etc/config/rpcd`.

The exact host ACL arrays and the no-`ubus log.read` invariant remain covered
separately by `tests/fwlive-rpcd-security.test.js`; this artifact is only the
installed authenticated-session evidence.
